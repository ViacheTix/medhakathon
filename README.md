# Medical Insight — Text-to-SQL Agent for Healthcare Analytics

AI-агент для анализа медицинских данных: пользователь задаёт вопрос на естественном языке — агент транслирует его в SQL, выполняет запрос к базе данных и возвращает структурированный ответ с автоматической визуализацией.

**[Live Demo](https://medhakathon-m2ngerulzguk38ozyzs3pp.streamlit.app/)**

---

## Архитектура и механика работы

Запрос пользователя проходит через трёхэтапный pipeline:

**1. Генерация SQL (NL → SQL)**
LLM получает схему базы данных, few-shot примеры и историю диалога, после чего генерирует DuckDB-совместимый SQL. Промпт включает правила выбора таблиц (витрины vs. сырые данные), маппинг JOIN-связей и медицинские синонимы для расширения поискового покрытия (например, "нос" → `ринит | синусит | риноррея`).

**2. Self-Correction Loop**
Если сгенерированный запрос возвращает ошибку или пустой результат, агент запускает цикл самокоррекции (до 3 попыток): LLM получает исходный SQL и сообщение об ошибке, затем переписывает запрос. Обрабатываются оба сценария: синтаксические ошибки и семантически пустые результаты.

**3. Интерпретация и визуализация**
Результаты выполнения SQL передаются в LLM для генерации аналитического вывода. Если ответ содержит числовые данные, автоматически строится интерактивный график (Plotly).

```
User query
    │
    ▼
NL → SQL (LangChain + LLM)
    │
    ▼
Execute (DuckDB)  ──→  Error / Empty?  ──→  Self-Correction (up to 3x)
    │
    ▼
DataFrame (CSV)
    │
    ▼
LLM Analysis  +  Auto Chart (Plotly)
    │
    ▼
Response to user
```

### Управление контекстом диалога

Агент сохраняет историю запросов и передаёт последние 4 сообщения (2 пары вопрос-ответ) в контекст LLM. Это позволяет обрабатывать уточняющие вопросы без потери контекста: `"А для женщин?" → "В каком районе?"` корректно маппятся на предыдущий логический запрос.

## База данных

DuckDB с моковыми медицинскими данными Санкт-Петербурга (~1.4M строк):

| Таблица | Тип | Описание |
|---|---|---|
| `prescriptions` | Raw | 1 млн фактов выдачи рецептов |
| `patients` | Reference | 379k пациентов (пол, дата рождения, район) |
| `drugs` | Reference | 3k препаратов (название, стоимость, дозировка) |
| `diagnoses` | Reference | 14k кодов МКБ-10 с расшифровками |
| `insight_cost_by_disease` | Mart | Агрегаты: стоимость лечения по группам болезней |
| `insight_gender_disease` | Mart | Агрегаты: половозрастные профили заболеваний |
| `insight_region_drug_choice` | Mart | Агрегаты: популярность препаратов по районам |

В промпт передаётся smart-схема с описаниями таблиц и явными правилами JOIN. Агент приоритизирует обращение к витринам (marts) как к более быстрым источникам предагрегированных данных.

## Стек

**Backend / Agent**
- Python 3.10+
- LangChain — оркестрация цепочек (ChatPromptTemplate, LCEL)
- OpenRouter API — доступ к LLM (Llama 3.3 70B Instruct)
- DuckDB — аналитическая in-process база данных

**Frontend**
- Streamlit — веб-интерфейс и state management
- Plotly — интерактивные графики

## Запуск локально

```bash
git clone https://github.com/ViacheTix/medhakathon
cd medhakathon
pip install -r requirements.txt
```

Создайте `.env` в корне проекта:

```
OPENROUTER_API_KEY="your_key_here"
```

```bash
streamlit run main.py
```

Приложение доступно по адресу `http://localhost:8501`. Ключ также можно ввести через интерфейс при первом запуске.

## Возможности

- **Text-to-SQL** с контекстом диалога и поддержкой уточняющих вопросов
- **Self-correction loop** — автоматическое исправление SQL при ошибках и пустых результатах
- **Медицинские синонимы** в промпте — расширение запросов бытовой лексики до МКБ-терминологии
- **Аналитический дашборд** с готовыми инсайтами и интерактивными графиками
- **Автовизуализация** — графики генерируются автоматически при наличии числовых данных в ответе
